Phase 2 (Previous):
  • Only 3-column CSV format (Old ID | New ID | New Name)
  • Manual old-ID selection from dropdown
  • No tracking of availability
  • Single mode operation

Phase 3 (Current - Dual Format):
  • TWO CSV formats (2-col auto OR 3-col manual)
  • Format A: Auto-detect Barclays IDs, auto-assign slots
  • Format B: Manual replacement of specific users
  • Availability tracking via replacement_status column
  • FOUR modes total (bulk A/B + single A/B)
  • Clear mode selection in UI
  • Better instructions with examples
  • Works even when slots exhausted (use Mode B)


⚙️ DATABASE CHANGES:
════════════════════════════════════════════════════════════════════════════

Schema Addition:
  Table: users
  New Column: replacement_status
  Type: ENUM('available', 'replaced')
  Default: NULL
  Comment: Tracks if pre-created user (BS10030X) can be replaced

Initialization:
  All BS1003xx users: status = 'available' (100 slots)
  All other users: status = NULL
  Non-pre-created users unaffected

Format B Behavior:
  • Ignores replacement_status
  • Always allows replacement
  • Perfect for manual reassignments
