ARCHITECTURE: WHY PERMISSION SYSTEM EXISTS
================================================================================

Without User-Scoped Flags (BAD):
  User 1 reads flag      → /tmp/flag_g9.txt
  User 2 overwrites flag → /tmp/flag_g9.txt (SAME FILE!)
  User 1 submits file    → Gets User 2's flag (WRONG!)
  Result: Incorrect CTF credits

With User-Scoped Flags (GOOD):

SANDBOX PROTECTION LAYERS
================================================================================

Layer 1: Command Whitelisting
  ✓ cat, ls, head, tail, wc, echo, id, whoami, pwd
  ✗ rm, cp, curl, wget, env (full), etc.

Layer 2: User ID Tracking
  ✓ Each Sandbox instance knows current user's ID
  ✓ Permission checks use user ID comparison

Layer 3: Filename-Based Permission Check
  ✓ Pattern: flag_g9_(\d+).txt
  ✓ Extract user ID: 1, 2, 3, ...
  ✓ Compare to current user
  ✓ Block if different

Layer 4: Filesystem Confinement
  ✓ All paths confined to /tmp
  ✓ Path traversal blocked (../ escapes prevented)

Layer 5: Ephemeral Flag Lifecycle
  ✓ Flag created when exploit triggered
  ✓ Flag deleted after command executes
  ✓ No persistent flag access

TECHNICAL DETAILS: PERMISSION CHECK CODE
================================================================================

Sandbox.php line 47-53:

    private function isOtherUserFlagFile(string $basename): bool
    {
        if (preg_match(self::FLAG_FILE_PATTERN, $basename, $m)) {
            return (int) $m[1] !== $this->uid;  // ← KEY LINE
        }
        return false;
    }

How it works:
  1. Check if filename matches pattern: flag_g9_(\d+).txt
  2. Extract number: $m[1]
  3. Compare with current user: (int) $m[1] !== $this->uid
  4. Return TRUE if DIFFERENT user (file blocked)
  5. Return FALSE if SAME user (file allowed)
