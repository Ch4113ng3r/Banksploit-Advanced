🔴 SQL Injection (SQLi)

What is it?

An attacker inserts malicious SQL code into input fields to manipulate database queries.

Example:

-- Normal login query SELECT * FROM users WHERE customer_id = 'BS100234' AND password = 'mypass' -- If we inject: BS100234' OR '1'='1 SELECT * FROM users WHERE customer_id = 'BS100234' OR '1'='1' AND password = 'mypass' -- Result: Always TRUE → Login bypassed!

Real-World Impact:

  • Bypass authentication (login without password)
  • Extract sensitive data (customer info, transactions)
  • Modify or delete database records

🟠 Insecure Direct Object References (IDOR)

What is it?

An application exposes direct references to objects (like account IDs or user IDs) without proper authorization checks.

Example:

-- You login as user A (account_id = 1) -- You try to view statements for: /statements?account_id=4 -- Server returns statements for account_id=4 (belongs to user B) -- No check: "Does user A own account 4?"

Real-World Impact:

  • View other users' bank statements
  • Steal money from other accounts
  • Access sensitive personal information

🟡 JWT Algorithm Confusion

What is it?

JSON Web Tokens (JWT) are vulnerable when the server doesn't properly validate the algorithm used to sign them.

The Attack - "alg: none":

// Attacker creates JWT with no signature { "header": {"alg": "none"}, "payload": {"role": "admin", "user_id": "123"}, "signature": "" } // Server accepts it as valid // Attacker is now "admin"!

Real-World Impact:

  • Forge admin tokens without password
  • Elevate privileges from user to admin
  • Bypass authentication entirely

🔴 Command Injection

What is it?

An application executes system commands with unsanitized user input, allowing attackers to inject arbitrary commands.

Example:

// Application converts PDF (using wkhtmltopdf) $filename = $_GET['file']; // User input exec("wkhtmltopdf /files/$filename output.pdf"); // Attacker injects: file.pdf; rm -rf / exec("wkhtmltopdf /files/file.pdf; rm -rf / output.pdf"); // Server deletes all files!

Real-World Impact:

  • Execute arbitrary commands on server
  • Delete files or entire system
  • Install malware or backdoors
  • Access sensitive files

🚩 Where Flags Are Hidden

Flags are revealed when you successfully exploit a vulnerability:

Flag Locations:

  • In Modal Popups: "🚩 FLAG CAPTURED!" dialog appears with flag text
  • In HTTP Headers: Check X-CTF-Flag header (use Inspector or DevTools)
  • In API Responses: JSON responses from special endpoints contain flags
  • Browser Console: JavaScript logs may show flag values

How to Capture a Flag:

  1. Successfully exploit a vulnerability
  2. A modal or alert shows your flag
  3. Copy the flag (format: BANKSPLOIT{...})
  4. Go to Lab Mode Dashboard → Challenges
  5. Paste flag and click Submit
💡 Tip: Each user gets a unique flag for each vulnerability. You cannot share flags with others.

💻 How to Approach: No Special Tools Required

All you need:

  • A web browser (Chrome, Firefox, etc.)
  • Browser Developer Tools (Press F12)
  • A text editor or notepad
  • Your brain! 🧠

Step-by-Step Approach:

1. Understand the vulnerability: Read the explanation and examples above
2. Identify vulnerable input: Find fields that accept user input (login, search, forms)
3. Test the payload: Try the injection/manipulation described in hints
4. Observe the result: Check if the app behaves unexpectedly
5. Capture the flag: Look for the flag in modal, headers, or console
6. Submit for points: Verify flag format and submit in Lab dashboard
